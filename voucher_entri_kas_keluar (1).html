Mode Purwarupa Lokal (Belum Terhubung Supabase)

Ketentuan Pengisian Jurnal Kas Keluar:

  • Tombol Submit Voucher aktif jika minimal terdapat 2 baris jurnal valid, total debit = total kredit, dan selisih 0.
  • Setiap baris wajib mengisi akun valid serta hanya bernilai salah satu (Debit ATAU Kredit positif).
  • Jurnal berstatus POSTED terkunci permanen; koreksi wajib menggunakan Reversing Entry.

Skema PostgreSQL (Supabase) & Keamanan Integritas

Salin skrip SQL di bawah ini ke SQL Editor pada dashboard Supabase Anda untuk membuat struktur tabel secara lengkap beserta constraint immutability status POSTED.

schema_accounting.sql 
-- 1. Tabel Chart of Accounts (CoA)
CREATE TABLE IF NOT EXISTS chart_of_accounts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    account_code VARCHAR(50) UNIQUE NOT NULL,
    account_name VARCHAR(150) NOT NULL,
    account_type VARCHAR(50) NOT NULL, -- Asset, Liability, Equity, Revenue, Expense
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Tabel Journal Headers (Header Voucher Kas Keluar)
CREATE TABLE IF NOT EXISTS journal_headers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    voucher_no VARCHAR(50) UNIQUE NOT NULL,
    tx_date DATE NOT NULL,
    description TEXT NOT NULL,
    status VARCHAR(20) DEFAULT 'DRAFT', -- DRAFT, POSTED, REVERSED
    total_amount NUMERIC(15, 2) NOT NULL DEFAULT 0,
    created_by VARCHAR(150) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    hash_checksum VARCHAR(64) NOT NULL
);

-- 3. Tabel Journal Lines (Baris Detail Jurnal Akuntansi)
CREATE TABLE IF NOT EXISTS journal_lines (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    journal_id UUID REFERENCES journal_headers(id) ON DELETE CASCADE,
    account_code VARCHAR(50) REFERENCES chart_of_accounts(account_code),
    debit NUMERIC(15, 2) DEFAULT 0 CHECK (debit >= 0),
    credit NUMERIC(15, 2) DEFAULT 0 CHECK (credit >= 0),
    CONSTRAINT chk_debit_or_credit CHECK (
        (debit > 0 AND credit = 0) OR (credit > 0 AND debit = 0)
    )
);

-- 4. Tabel Audit Logs
CREATE TABLE IF NOT EXISTS audit_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    action VARCHAR(50) NOT NULL,
    voucher_no VARCHAR(50),
    user_identity VARCHAR(150) NOT NULL,
    details TEXT,
    timestamp TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 5. Trigger Database: Mencegah UPDATE atau DELETE pada Voucher berstatus POSTED
CREATE OR REPLACE FUNCTION prevent_posted_mutation()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.status = 'POSTED' THEN
        RAISE EXCEPTION 'Pelanggaran Integritas: Jurnal dengan status POSTED tidak boleh diubah atau dihapus. Gunakan reversing entry.';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_prevent_posted_update
    BEFORE UPDATE ON journal_headers
    FOR EACH ROW
    EXECUTE FUNCTION prevent_posted_mutation();

CREATE TRIGGER trg_prevent_posted_delete
    BEFORE DELETE ON journal_headers
    FOR EACH ROW
    EXECUTE FUNCTION prevent_posted_mutation();

Panduan Singkat Skenario Pengujian Sistem

1. Skenario Jurnal Seimbang

Masukkan baris 1 (Beban Gaji) Debit Rp 5.000.000 dan baris 2 (Kas di Bank) Kredit Rp 5.000.000. Tombol submit akan aktif karena selisih 0 dan baris valid.

2. Skenario Jurnal Tidak Seimbang

Masukkan Debit Rp 5.000.000 dan Kredit Rp 4.000.000. Sistem menampilkan status Unbalanced dan tombol submit otomatis terkunci.

3. Skenario Nominal Negatif

Input nilai debit atau kredit di bawah 0. Validasi frontend & database menolak nilai negatif serta mewajibkan eksklusivitas (debit atau kredit saja).

4. Skenario Modifikasi Jurnal POSTED

Coba edit atau hapus voucher yang sudah berstatus POSTED. Sistem akan menolak secara mutlak sesuai aturan akuntansi baku.
